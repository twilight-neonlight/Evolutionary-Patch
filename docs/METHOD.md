# 방법 명세 (2026-10-16 확정본)

Main 저장소 구성의 기준 명세다. 이식하는 기존 코드(Lite 300 기준본)와 이 문서가 다르면 이 문서를 따르고, 다른 곳을 모두 보고한다. "미결정"으로 표시한 항목은 현재 기본값으로 구현하되 설정으로 바꿀 수 있게 한다.

## 1. 전체 구조

전처리(재현 테스트, 회귀 테스트, 위치 정보) → 초기 개체군 생성(진화 루프에 들어가기 전) → 진화 루프(적합도 평가 → 종료 확인 → 자식 생성 → 평가 → 다음 세대).

## 2. 전처리

- **재현 테스트:** 제3자 연구 산출물(이슈 본문과 base 코드베이스만으로 생성된 테스트)을 쓴다. 기존 테스트 파일에 연결 가능하고 base에서 테스트가 1개 이상 수집되면 사용한다. base에서 이미 통과하는 테스트도 그대로 사용한다. 사용할 수 없으면 LLM으로 생성한다(prep ②).
- **회귀 테스트:** Agentless의 사전 계산 산출물(select_regression의 tests_passing_in_original_repo)을 받아 쓴다.
- **위치 정보:**
  1. prep ①: 이슈와 비테스트 소스 파일 목록으로 후보 소스 파일 최대 3개를 고른다.
  2. 재현 테스트를 base에서 1회 실행한다(이 결과는 repro_on_base로도 기록).
  3. 위치 호출(V2): 이슈, 후보 파일의 base 코드(예산 12,000토큰, full → skeleton → skeleton_drop → skeleton_truncated), 재현 테스트 소스, base 실행 출력 → 파일·함수(메서드) 위치 최대 3개.
  4. 대체 순서: V2가 위치를 못 내면 prep ②의 위치 → 제3자 연구 산출물의 위치 정보 → 모두 없으면 prep 실패(빈 패치, 미해결, 분모 포함).
- **위치 범위:** 첫 데코레이터 줄부터 끝 줄까지. 클래스 식별자면 클래스 본문 전체.
- 전처리를 한 번의 호출로 줄이는 설계는 이번에 적용하지 않는다.

## 3. 초기 개체군

- 한 번의 호출로 패치 N=10개를 서로 다른 접근으로 작성하게 한다. 입력은 이슈, 위치 코드, N뿐이다.
- 각 패치는 유효성 검사(5절)를 거친다. 유효한 패치가 N개보다 적으면 부족분만 최대 2회 다시 요청하고, 직전 응답의 무효 사유별 안내를 붙인다. 그래도 부족하면 무효 후보로 채운다.
- 생성된 패치를 평가한다(4절).
- **0세대 분기:** 유효 후보가 0개면 빈 패치, 1개면 그 후보를 제출하고 진화하지 않는다. 2개 이상이면 진화 루프로 간다.

## 4. 적합도

- 적합도 (r, g): r = 재현 테스트 통과 여부(1개 이상이고 모두 PASSED), g = 회귀 테스트 통과 개수. 사전식으로 비교한다.
- 무효 후보는 실행하지 않고 모든 유효 후보보다 아래에 둔다.
- **완전 통과:** 유효, 오류·시간 초과 없음, r = 1, g = g_total. 회귀 테스트가 없는 이슈는 r = 1만으로 판정한다.
- 순위 동점은 나중 세대에서 태어난 후보를 우선하고, 같은 세대면 후보 번호 순이다(newer_first).
- 한 이슈 안에서 같은 패치(patch_hash)는 한 번만 실행하고 결과를 재사용한다.

## 5. 유효성 검사

- 검색 블록이 위치 범위 안의 원본 코드와 일치한다(줄 단위 앞뒤 공백 차이 허용, 들여쓰기 보정 규칙 유지).
- 수정이 위치 정보의 파일과 함수 범위 안이다(수정 범위 S0).
- 적용 결과가 원본과 다르다(빈 diff는 무효).
- 적용한 코드가 compile()로 컴파일된다.

## 6. 진화 루프 (세대 k = 0 … K−1)

1. 완전 통과 후보가 있으면 그중 순위 최상위를 최종 패치로 채택하고 종료한다(조기 종료).
2. 마지막 세대(k = K−1)면 순위 최상위를 채택하고 종료한다.
3. **부모 선택:** 현재 개체군에서 부모 쌍 N/2개를 독립적으로 뽑는다. 순위 i인 후보의 확률은 p_i = 2(N − i + 1) / (N(N + 1))이다. 적합도가 같은 후보들은 해당 순위 확률의 평균을 나눠 갖는다. 같은 후보가 한 쌍에 두 번 뽑혀도 허용한다.
4. **교배(쌍마다 LLM 1회):** 입력은 이슈, 위치 코드, 두 부모의 diff(무효 부모는 원문과 무효 표시), 각 부모의 테스트 실행 결과(7절)다. 두 수정을 의미적으로 결합한 패치 하나를 원본 코드 기준으로 쓴다.
5. **교배 재시도:** 유효성 검사에 실패하면 직전 답변(끝 6,000자)과 유효성 실패 원인을 덧붙여 최대 R = 2회 다시 요청한다. 그래도 무효면 그 자식은 최하위 무효 후보로 남는다.
6. **변이:** 교배와 재시도가 끝난 뒤 자식마다 확률 p_m = 0.15로 변이 여부를 정한다. 교배 자식이 무효여도 변이를 시도한다. 입력은 교배와 같다(이슈, 위치 코드, 두 부모 diff, 두 부모의 테스트 실행 결과). 같은 지점을 다른 접근으로 다시 구현한 패치 하나를 쓴다. 재시도하지 않고, 변이 결과가 무효면 변이를 취소하고 교배 자식을 쓴다.
7. 새 자식 N/2개를 평가한다.
8. **세대 교체:** 다음 세대 = 현재 개체군의 상위 N/2(유효 여부와 무관) + 새 자식 N/2. 개체군 크기는 N으로 유지된다.

## 7. 부모의 테스트 실행 결과 (교배·변이 입력)

부모별로 다음을 넣는다. 모든 항목에 문자 상한을 둔다.
- 재현 테스트 통과/실패
- 테스트별 상태 최대 20개
- 재현 테스트 출력 마지막 40줄(문자 상한)
- 재현 테스트 소스(상한 2,000토큰)
- 회귀 결과:
  - 실패가 있으면 "통과하지 못한 회귀 테스트 N개"와, 실패한 회귀 테스트 최대 3개의 오류 내용(부모당 약 1,500자). 오류 내용은 예외 종류·메시지와 저장소 소스 프레임만 남긴다. 테스트 ID·이름은 지우고, 테스트 파일 프레임은 `<test frame>`으로 바꾸고, test_files 마스킹을 적용한다. 추출하지 못한 테스트는 N에만 포함한다.
  - 실패가 없으면 "회귀 테스트 실패 없음"
  - 회귀 테스트가 없으면 "회귀 테스트 없음"
  - 회귀 테스트의 전체 개수와 통과 개수는 넣지 않는다.
- 무효 부모는 "실행되지 않음"
- 실행이 시간 초과로 끝났으면 그 사실

입력 한도는 28,672토큰(32,768 − 4,096)이다. 넘으면 회귀 오류 내용 → 재현 테스트 소스 → 재현 출력 순으로 줄이고, 이슈와 위치 코드는 줄이지 않는다.

## 8. 설정값

| 항목 | 값 |
|---|---|
| N / K / p_m / R | 10 / 5(0세대 포함, 세대 갱신 최대 4회) / 0.15 / 2 |
| 온도 | init 0.7, crossover 0.5, mutation 0.7, prep 0.7 (top_p 1.0, top_k 끔, 반복 페널티 1.0) |

## 9. 프롬프트

- 모든 프롬프트 문장은 고정 문서 하나에만 있다. 코드는 구간 선택과 자리표시자 채우기만 한다.
- 현재 문서는 A타입(기존 코드가 만드는 문장을 그대로 옮긴 것)이다.
- B타입(Agentless 구조와 v4 형식: 문맥 태그, 할 일과 이유, 예시 하나, 이유를 붙인 긍정형 규칙, 결과 앞에 분석·설명을 쓰지 않음)으로의 교체는 미결정이다. 교체할 때는 모든 프롬프트를 한 타입으로 통일한다.

## 10. 평가와 어블레이션

- 해결률 분모는 전체(Lite 300, Verified 500)다. 이슈별 해결 여부를 저장한다.
- K ∈ {1, 3, 5} 어블레이션은 K = 5 실행 기록을 해당 세대에서 끊은 제출 패치를 채점해 얻는다.
- 정답 정보로 나눈 그룹(테스트 F→P 유효 여부)은 분석용으로만 쓴다.

## 11. 정답 정보 격리

위치·패치 생성에 정답 패치, 정답 위치, SWE-bench 평가용 테스트를 쓰지 않는다. 회귀 테스트의 이름과 경로는 어떤 프롬프트에도 넣지 않는다. 정답 필드는 채점과 분석 코드에서만 읽는다.
